Database Migrations Checklist

Drizzle ORM schema is partitioned into 8 historical SQL migrations located under backend/drizzle/. These must be executed remotely on the database instance: 

npx wrangler d1 migrations apply krishna-sanjeevani-db --remote

R2 Storage Architecture

Tracks are stored inside a private bucket. Uploads are placed under songs/uploads/ temporarily, and moved to songs/processed/ post-transcoding. The R2 bucket has no public URL endpoint, preventing hotlinking.

Queues & Media Pipeline

The media consumer worker segments audio files, generates HLS segment playlists, uploads them to R2, and deletes the original MP3. This processing occurs asynchronously to prevent gateway timeouts.

HLS Secure Streaming

Streaming requires a 5-minute session ticket. The Worker validates the ticket and fetches segment files from R2, preventing direct asset URL hotlinking. While HLS prevents direct downloads, a client capable of playing the media necessarily receives the data.

Subscription Payments

Subscription access tiers are verified inside the database. The payment provider integration operates in mock mode for testing, but is ready to connect to Razorpay APIs in production.

Security & Vulnerabilities Analysis

  • Access Tokens: HS256 JWT tokens verified at the edge.
  • Session Invalidation: Immediate token revocation upon replay detection.
  • Admin Role Gates: Protected by Hono requireRole middleware checks.
  • Direct R2 Exposure: Blocked. All assets are proxied through edge workers.
